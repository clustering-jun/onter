# 웹 설계 메모 (구현 전 계획)

알고리즘과 분리한 기록이다. 지금은 웹을 만들지 않는다. 여기에는 (1) 모듈 산출물을 화면에 어떻게 올릴지, (2) **모델링에는 쓰지 않았지만 화면에는 보여 주면 좋은 것**, (3) 사용자가 정하는 설정을 적는다.

## 1. 화면 흐름(단지 하나 기준)

| 단계 | 화면 | 쓰는 산출물 |
|---|---|---|
| ① 현황 | 단지 카드, 필요 6분야 막대(구간 표시), 공급·어긋남, 유형, 이력 | `outputs/m1_complex_profile.csv` |
| ② 사례 | 구성이 닮은 단지 / 가까운 단지 탭, 프로그램별 사례 카드 | `m2_complex_peers.csv`, `recommendations_detail.jsonl`의 evidence |
| ③ 순위 | 전체 상위 10개, 분야별 3개(신규·유지·재개), 근거 문장 | `m3_recommendations_top10.csv`, `m3_ranking_by_domain.csv` |
| ④ 실행 검토 | 점검표, 제약 입력, 연간 묶음과 달력 | `m4_program_requirements.csv`, `m4_complex_capacity.csv`, `m4_default_plan.csv` |

## 2. 화면 원칙(실험에서 나온 것)

- 추천은 **'검토 후보'**로 부른다. 점수 대신 근거를 앞에 둔다: "비슷한 단지 20곳 중 7곳이 운영".
- 필요 지수는 **구간과 함께** 보여 준다. N5처럼 구간이 넓은 분야는 흐리게 그린다.
- 필요 지수가 '고령·영구임대' 한 축에 묶여 있다는 점을 숨기지 않는다. 분야별 막대 옆에 쓰인 지표 이름을 펼쳐 볼 수 있게 한다.
- 이웃은 **두 종류를 따로** 보여 준다: 구성이 닮은 단지(멀리 있음)와 가까운 단지(같은 지사, 협력기관 공유).
- 실행 가능성은 **점수로 줄 세우지 않는다.** 항목별 상태(협력 이력 있음 / 가까운 시설 있음 / 없음)로만 보여 준다.
- '주거복지사 의존' 프로그램 23종에는 표시를 달고, 미배치 단지에는 "배치 단지에서 주로 운영됨"을 알린다.
- 비용은 항상 "추정"이라고 쓰고 등급(5단계)을 먼저 보여 준다.
- 조절 손잡이 두 개를 사용자에게 연다: **필요 반영 정도(w)** 와 **분야 고르게(λ)**. 교환 곡선(`f2_tradeoff.png`)을 미리보기로 붙인다.

## 3. 모델링에는 안 썼지만 화면에 올릴 것

| 자료 | 위치 | 모델에 안 쓴 이유 | 화면에서의 쓰임 |
|---|---|---|---|
| 고독사 기록(2019~2026) | 통합표 | 통합표 명세상 별도 결과. 훅·입력 금지 | 올리지 않는다. 내부 점검 표에만 |
| 해피콜 관리소 만족도 | happycall management_scores | 공급·필요 정렬과 무관(ρ≈0), 소표본 | 현황 화면에 참고 수치(표본 수와 함께). 통합 관리소 4곳은 표시 안 함 |

## 4. 사용자가 정하는 설정(모듈 4)

| 설정 | 기본값 | 알고리즘 입력 |
|---|---|---|
| 연간 추가 예산(공단 쪽 부담분) | 100만 원 | `plan(budget=)` |
| 연간 인력 한도 | 80명×시간 | `plan(load=)` |
| 프로그램 수 | 6개 | `plan(n_max=)` |
| 꼭 넣을 분야 | 필요 상위 2개 분야에서 1개씩 | `plan(min_per_domain=)` |
| 쓸 수 있는 공간 | 통합표의 시설 유무 | `allowed`로 걸러 냄 |
| 협력 가능한 기관 | 이력·가까운 시설 | 점검표 상태, `allowed` |
| 제외할 프로그램 | 없음 | `allowed` |
| 필요 반영 정도 / 분야 고르게 | 0.2 / 0.25 | `onter_scores(w_need=)`, `calibrated_topk(lam=)`. w는 0~0.5 범위로 열어 두고 `e8_decision_table.csv`의 교환 관계를 같이 보여 준다 |

전문가 응답 반영으로 화면에 더할 것
- **미배치 경고**: 전문가가 주거복지사가 필요하다고 한 프로그램을 미배치 단지에 추천할 때 경고를 붙인다(`welfare_gap`). 추천의 약 4%.
- **요건 출처 표시**: 비용·인력·공간·기관이 전문가 검토값인지 기록 추정인지(`requirement_basis`). 초안 값은 접어서 보여 준다.
- **1회 비용·명×시간·부담 주체·난이도**를 점검표에 그대로 보여 준다. 연간 값은 '단지당 연간 기록 수'를 곱한 추정임을 밝힌다.
- **주거복지사 의존의 두 출처**(자료 기준, 전문가 기준)를 따로 표시한다.
- **'문화와 활동' 필요는 불확실**하다고 표시한다(가중치에 민감, 전문가 응답 안에서도 어긋남).

## 5. 기록 환류(설계만)

추천 → 채택 여부 → 실행 기록(참여자 수, 대상, 만족, 미참여 사유, 실제 비용) → 다음 추천. 지금 기록에는 결과 항목이 없다. 입력 화면은 표준 프로그램 자동 제안(검색 첫 순위 적중 74%)으로 부담을 줄이고, 실제 비용·인력 칸을 넣어 모듈 4의 추정값을 바꿔 나간다.

## 6. 구현 때 정할 것

- 산출물 갱신 주기(월 1회 일괄 계산이면 충분, 전체 2분).
- 제약 묶음 선택은 요청 때 계산(단지당 0.005초).
- 뉴스 본문·사례집 원문·단지별 수치의 공개 범위.
