## 1. 한 줄 요약

**도입 기록으로 '현장이 고를 만한 범위'를 잡고, 그 안에서 단지의 구조적 필요 쪽으로 기울인 뒤, 실행 요건을 점검표와 제약으로 붙인다.** 도입 기록을 정답으로 학습하지 않는다.

## 2. 왜 이렇게 설계했나(비판적 검토)

데이터를 돌려 보고 처음 생각을 세 번 고쳤다.

| 처음 생각 | 데이터가 보여 준 것 | 고친 설계 |
|---|---|---|
| 단지 특성에 맞춘 협업 필터링이 추천의 핵심이다 | 이웃·EASE·ALS·특징 릿지·GBDT 순위 학습 어느 것도 전국 채택률 기준선을 뚜렷이 넘지 못한다(NDCG@10 0.35 안팎) | 협업 신호는 '근거'로만 쓴다. 정교한 모델 대신 설명하기 쉬운 세 성분(비슷한 단지·함께 운영·채택률)만 남긴다 |
| 필요 적합 점수가 도입을 어느 정도 맞힐 것이다 | 필요 적합만 쓰면 무작위와 같다(AUC 0.51) | 도입 예측과 필요 정렬을 다른 축으로 놓고 교환 곡선에서 기본값을 고른다 |
| 실행 가능성 점수를 순위에 섞으면 현실성이 올라간다 | 규칙 기반 실행 가능성은 도입을 예측하지 못한다(AUC 0.48), 섞으면 나빠진다 | 실행 검토는 순위에 넣지 않고 점검표·제약·'주거복지사 의존' 표시로 쓴다 |
| 기록에서 추정한 비용·인력이면 충분하다 | 전문가 값과 비교하니 비용은 순위는 맞지만 1.5배 높고, 인력 부담은 약하게만 맞는다(ρ≈0.35) | 요건을 전문가 값으로 바꿨다. 전문가 요건의 실행 가능성은 도입을 맞히지만(AUC 0.59) 순위에 섞어도 이득이 없어 경고와 제약으로 쓴다 |

두 가지 편향을 구분했다.
- **현상 유지 편향**: 도입 기록을 정답으로 학습하면 관성·지사·규모를 복제한다. 문제 정의가 지적한 바로 그 현상이다.
- **전문가 편향**: 전문가 판정을 정답으로 학습하면 소수 평가자의 관점이 굳는다.

그래서 어느 쪽도 학습의 정답으로 쓰지 않고, 서로 다른 세 기준으로 **삼각 검증**한다: ① 새 도입 예측(현실성), ② 해피콜 수요 분포(주민 목소리, 전국 수준), ③ 전문가 판정(1명 응답, 반영함). 학습으로 정하는 값은 두 개(필요 가중 w, 보정 강도 λ)뿐이고, 그것도 검증 분할에서 규칙으로 골랐다.

전문가 응답이 보여 준 것(`02_experiments.md` 8절): 채택률·근거 점수는 전문가의 '실행할 수 있는가'와 맞고 '필요한가'와는 무관하다. 필요 적합은 그 반대다. 두 축을 따로 두고 섞는 설계가 전문가 판단과 같은 구도다. 전문가 우선 추천은 w를 0.3~0.5로 올리는 쪽을 가리켰지만 반반 검증의 구간이 0을 포함했고 평가자가 1명이라 기본값은 그대로 두었다.

## 3. 전체 구조

```
전처리 데이터(processed)
   │  data.py · features.py  (complex_id / std_id 조인, 기간을 받는 함수만 기록을 읽음 → 누수 차단)
   ▼
[모듈 1 프로파일] 필요 지수(6분야, 구간) · 공급 · 어긋남 · 목표 분포 Q · 유형 · 이력
   ▼                                   ▲ Q, 필요
[모듈 2 사례]  유사 단지(구조·필요·행동·거리·지사·혼합) · 기록 사례 · 사례집 카드 · 뉴스 · 프로그램 검색
   ▼ 이웃
[모듈 3 순위]  근거(이웃+EASE+채택률) ⊕ 필요 적합 → 필요 보정 재순위 → 전체 10개 + 분야별 3개
   ▼ 후보
[모듈 4 실행 검토] 요건 프로파일 · 단지 여건 · 점검표 · 제약 묶음 선택(정수계획)
   ▼
explain.py  근거 문장(템플릿, 선택적으로 LLM) → outputs/
```

## 4. 모듈 1: 단지 현황 지표와 프로파일 (`m1_profile.py`)

**필요 지수.** 분야 d의 필요 = 지표 백분위의 가중 평균을 다시 단지 간 백분위로 바꾼 값.

| 분야 | 구조 지표(기본) | 이용 실적(표시·점검용) |
|---|---|---|
| N1 안부와 관계 | 80세 이상 비율, 세대당 인구(−), 40㎡ 미만 세대 비율, 영구임대 | 홈닥터 생활지원 |
| N2 생활과 경제 | 영구임대, 40㎡ 미만 세대 비율, 평균 전용면적(−) | 홈닥터 경제지원 |
| N3 건강과 돌봄 | 70세·80세 이상 비율, 의원·병원·약국·보건기관 거리 | 홈닥터 의료·가사지원 |
| N4 주거환경과 생활안전 | 경과 연수, CCTV(−), 응급의료시설 거리, 80세 이상 비율 | 홈닥터 가사지원 |
| N5 문화와 활동 | 노인여가복지시설·종합사회복지관 거리, 단지 안 공간 종류(−), 60세 이상 비율 | 없음 |
| N6 일자리와 학습 | 20~59세 비율, 20세 미만 비율 | 없음 |

- 이용 실적을 기본값에서 뺀 이유: 이용은 공급이 있어야 생긴다. 넣어도 결과가 나아지지 않았다(절제).
- 도입 기록을 쓰지 않는 이유: 기록은 필요가 아니라 관성·규모·지사를 따른다.
- **불확실성**: 가중치를 로그정규(σ=0.5)로 300번 흔들고 지표를 하나씩 빼서 5~95% 구간을 낸다. N2·N6은 구간이 좁고(중앙 0.01~0.06), N5는 넓다(0.32). 화면에는 구간을 같이 보여 준다.
- **한계**: 여섯 분야의 첫 주성분이 69%다. N1~N4는 '고령·영구임대' 한 축으로 함께 움직인다. 단지별 1인 가구·수급·장애 비율을 받으면 분야를 가르는 힘이 생긴다(자료 요청 대상).

**공급·어긋남.** 분야별 1,000세대당 연 기록 수의 백분위. 어긋남 = 필요 백분위 − 공급 백분위. 필요 상위 1/3이면서 공급 하위 1/3이면 '우선 검토'.

**목표 분포 Q.** 추천 목록의 분야 구성이 닮아야 할 분포. `q(d) ∝ base(d)·exp(β·(필요 백분위 − 단지 평균))`, β=2.
- base 기본값은 해피콜 수요 응답(공단 관리 단지 응답)을 분야로 바꾼 '주민 목소리' 분포다. 현 공급 대비 '생활과 경제'가 높다(수요 23% 대 공급 12%).
- 단지 연령 구성으로 연령대별 응답을 가중한 합성 추정을 쓰지만, 단지 간 표준편차가 0.1~0.5%p라 사실상 전국 분포다. **해피콜은 단지를 가르지 못한다.** 단지를 가르는 것은 구조 필요의 기울기(β)다.

**유형.** 구조 특징 k-평균. 실루엣과 부트스트랩 ARI로 k=3(젊은 국민임대형 153, 고령 영구임대형 128, 원격형 37).

**이력.** 기록 있는 달 비율, 종류 수, 반복 비중, 2024·2025 자카드, 많이 한 프로그램, 협력기관 유형.

## 5. 모듈 2: 프로그램 사례 (`m2_cases.py`)

**'유사'의 정의 여섯 가지와 혼합.**

| 정의 | 만드는 법 | 성질 |
|---|---|---|
| demo / struct | 표준화 특징의 RBF | 주민·주거가 닮음, 멀리 있음 |
| need | 필요 백분위 6차원 RBF | 필요가 닮음 |
| behav | 프로그램별 기록 달 수 × idf의 코사인 | 운영이 닮음 |
| geo | 1/(1+km/10) | 79%가 같은 지사, 협력기관 공유 가능 |
| branch | 같은 지사 | 조직 관행 공유 |
| hybrid(기본) | 구조 0.5·행동 0.3·거리 0.2의 순위 평균 | 중간. 기록 없는 단지는 구조+거리 |

예측력은 정의 간 차이가 없다. 그래서 선택 기준을 '예측'이 아니라 '설명'에 둔다: 혼합 이웃을 근거 계산에 쓰고, 화면에서는 구성이 닮은 단지와 가까운 단지를 따로 보여 준다.

**사례 세 종류.**
1. 비슷한 단지의 활동 기록: 유사도 0.6·최근성 0.15·기록 정보량 0.25로 고르고 단지당 1건.
2. 사례집 근거 카드: 같은 프로그램 카드가 있으면 붙이고, 없으면 프로그램 유사도(분류·글·동시 운영의 순위 평균)가 0.97 이상일 때만 '비슷한 프로그램'으로 붙인다. 추천의 16%에 붙는다.
3. 뉴스: 제목과 링크만(본문 재사용 허락 미확인).

**프로그램 검색.** 글자 n-gram TF-IDF·LSA·BM25의 순위 융합. 처음 보는 활동 제목의 74%를 첫 순위에 맞는 표준 프로그램으로 잇는다. 새 기록 입력의 자동 분류 제안과 자유 검색에 쓴다.

## 6. 모듈 3: 프로그램 순위 (`m3_rank.py`)

1. **근거 점수** = 백분위 순위 평균(이웃 채택률 k=20, EASE λ=20, 전국 채택률).
2. **필요 적합** = Σ_d 필요(d)·소속(p,d) × (0.5 + 대상 적합). 소속은 프로그램 정의와 기록의 분야 표기를 반씩 섞은 행렬, 대상 적합은 프로그램의 통상 대상과 단지 주민 구성의 맞음.
3. **융합** = 0.8·근거 순위 + 0.2·필요 순위.
4. **필요 보정 재순위**(Steck 2018): 상위 K개를 고를 때 `(1−λ)·점수 − λ·KL(Q ‖ 목록 분야 분포)`를 탐욕적으로 최대화, λ=0.25.
5. **분야별 순위**: 분야마다 점수순 3개. 상태를 붙인다(신규 검토 / 유지 / 재개 검토).

w=0.2, λ=0.25는 검증 분할 A에서 '새 도입 재현율이 근거 모델의 90% 이상, 필요 정렬 0.95 이상인 구성 중 필요 적합 최대'라는 규칙으로 골랐다. 주 분할에서 재현율은 근거의 95%를 지키고 필요 적합은 0.52 → 0.68로 오른다.

비교한 방법: 무작위, 채택률(전체·최근·지사·유형), 확산 속도, 이웃 7종, 프로그램 kNN, EASE, SVD, ALS, 특징 릿지, 필요 적합, GBDT 순위 학습, 융합·2단계·보정 전략.

## 7. 모듈 4: 실행 검토 (`m4_feasibility.py`)

- **요건 프로파일**(프로그램 96종): 필요 자원 10종 비중, 협력기관 유형 비중과 표기율, 장소 유형(세대 방문·경로당·복지관·관리동·단지 밖·단지 안), 세대 방문 비중, 정기 운영 비중, 회차, 참여 규모, 많이 여는 달, 연간 비용(추정)과 등급, 인력 부담(상대 점수)과 등급.
- **단지 여건**: 주거복지사 배치, 공간 6종, 협력기관 유형별 여건(이력 있음 1 / 가까운 시설 0.7 / 없음 0.3), 운영 규모.
- **점검표**: 프로그램×단지마다 자원, 협력기관과 여건, 장소, 인력·비용 등급, 시기, 예상 걸림돌과 사례집의 해결 전략.
- **주거복지사 의존 표시**: 영구임대 단지에서 규모로 층화한 Mantel-Haenszel 오즈비의 95% 하한이 1을 넘는 23종.
- **제약 묶음 선택**: 사용자가 연간 예산, 인력 부담 한도, 개수, 분야별 최소 개수, 허용 프로그램을 정하면 정수계획(scipy HiGHS)으로 고른다. 탐욕 선택은 최적의 63~90%이고 제약을 어기기도 해서 쓰지 않는다.

**전문가 요건 반영.** `apply_expert()`가 시트 B의 1회 비용·명×시간·필수 공간·필수 협력기관·주거복지사 필요 여부·난이도를 덮어쓴다(초안은 `_draft` 열). 연간 비용은 공단 쪽 부담분, 인력은 연간 명×시간 단위가 됐다. `feasibility_expert()`는 요건만 전문가 값으로 바꾼 규칙 점수이고(학습 없음), 표시와 '주거복지사 필요인데 미배치' 경고에 쓴다. 묶음 선택의 기본 제약은 예산 100만 원·인력 80명×시간으로 바꿨다. 주거복지사 의존은 자료 기준 23종과 전문가 기준 18종을 같이 싣는다(카파 0.35).
