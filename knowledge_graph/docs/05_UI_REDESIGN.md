# 지식 지도 UI 재설계 — 2026-11-18

## As-is: 실제 탐색 흐름에서 발견한 문제

| 영역 | 기존 문제 | 사용에 미치는 영향 |
|---|---|---|
| 화면 구성 | 큰 통계, 상단 도구, 하단 경로 기능, 중복 미리보기가 동시에 노출 | 핵심 지도 공간이 작고 우선순위가 불명확 |
| 클릭 | 축소된 화면에서도 최소 0.65배로 강제 확대 | 클릭 한 번에 배율이 두 배 이상 바뀌고 주변 맥락이 사라짐 |
| 사례 읽기 | 카드의 내용 버튼도 전체 지도 교체를 실행 | 읽으려던 순간 지도가 바뀌어 탐색 위치를 잃음 |
| 배치 | 노드를 놓거나 패널 크기가 변할 때 전체 재배치/맞춤 | 사용자가 만든 배치와 카메라 위치가 사라짐 |
| 글자 | 모든 이름을 큰 화면 글자 크기로 보정, 빈 label 설정에 의존 | 실제 숨김이 적용되지 않아 이름이 겹침 |
| 휠 | 그래프 라이브러리 민감도 값만 조정 | 사용자 환경에서 기대한 체감 변화가 부족 |
| 명칭 | 주변 관계 펼치기, 현재 지도에 추가, 고급 경로 도구가 한 줄 | 지도 교체와 추가, 읽기를 구분하기 어려움 |
| 좁은 화면 | 상세 정보가 큰 영역을 차지하고 중복 카드도 표시 | 지도를 보면서 내용을 확인하기 어려움 |

## To-be: 대상 찾기 → 연결 살펴보기 → 내용과 근거

- 상단은 64px 내비게이션과 43px 자료 범위로 압축. 큰 수치 카드를 제거하고 그래프 높이 확보.
- 왼쪽은 검색과 대표 탐색 3개. 자료·연결 필터는 펼침 영역으로 이동.
- 가운데는 제목, 패널 제어, 지도와 일관된 하단 확대 도구. 배율을 숫자로 표시.
- 오른쪽은 제목, 주요 동작 2개, 내용/사례·뉴스/관계 탭. 중복 노드 미리보기 제거.
- 덜 자주 쓰는 내보내기·애니메이션은 화면 설정, 두 대상 경로는 별도 펼침 영역으로 이동.
- 해피콜 관리소는 검색 종류에서 제외. 자료 자체를 삭제하지 않음.

## 동작 규칙

1. 노드 클릭: 노드 좌표와 연결은 유지. 카메라만 280ms 동안 중심 이동하고 배율을 1.12배로 올림. 같은 노드 반복 클릭 시 추가 확대하지 않음. 최소 배율 강제 상승 제거.
2. 사례 카드의 읽기 버튼: 상세 내용과 선택 강조만 변경. 지도 중심·노드 집합·좌표·배율은 그대로 유지.
3. ‘이 대상 중심으로 탐색’: 사용자가 명시적으로 선택했을 때 새 지도 로드 및 자동 맞춤.
4. ‘연결 추가’: 기존 노드와 카메라를 보존하고 새 노드만 주위에 배치. 추가 후 전체 맞춤하지 않음.
5. 노드 드래그: 놓은 위치 유지. 다른 노드를 다시 배치하지 않음.
6. 패널 열기/닫기, 창 크기 변경: 캔버스만 리사이즈. 자동 재배치/카메라 맞춤하지 않음. 전체 보기는 별도 버튼.
7. 휠: 라이브러리 기본 휠을 끄고 캔버스의 wheel 이벤트 직접 처리. deltaMode 정규화 후 ±100 제한, 배율 계수 exp(-delta*0.0055), 포인터 아래 좌표를 기준으로 보간. -40px는 약 1.246배, -100px는 약 1.733배. Ctrl 없이 동작하며 페이지 스크롤과 중복 실행 방지.
8. 라벨: 기본 11px, 선택 12px, 한 줄 축약. 렌더러가 측정한 실제 영역으로 충돌을 제거하고 표시 수를 12/22/36개로 제한. 빈 문자열 대신 text-opacity로 확실히 숨김. 전체 이름은 호버와 상세 패널에서 확인. 툴바 영역도 충돌 대상으로 예약.
9. 신규 지도는 간단히 보기(관계 제한 20)부터 시작. API의 종류별 우선 포함 규칙으로 실제 표시 노드는 20개를 초과할 수 있으며 하단에 실제 수를 표시.
10. 좁은 화면에서는 검색과 상세를 닫을 수 있는 패널로 사용. 모든 폭에서 가로 스크롤 방지.

## 검증 및 플랫폼 통합 시 유지할 계약

- Edge 1600×1000: 30개 노드 지도, 상세 레시피 렌더, JavaScript 오류 없음. wheel -40 입력으로 배율 1.1246 → 1.4014 확인.
- 실제 인앱 브라우저 좁은 화면: 짧은 위쪽 스크롤 0.15 입력으로 34% → 59%, 레시피 노드 클릭으로 66% 확인. 클릭 전후 노드 집합은 30개/32개 연결로 유지.
- 기존 서버 API, 그래프 의미/출처 구분, 원자료 및 모델 산출물은 변경하지 않음.
- 향후 웹 플랫폼에서도 ‘선택(읽기)’과 ‘탐색 중심 변경’, ‘증분 추가’를 별도 상태/동작으로 유지해야 함. 카메라는 사용자 상태로 보존하고, 자동 재배치는 새 지도 생성과 명시적 재배치에만 허용.
- 스크린샷: 13_redesign.png(개편 기본 화면), 14_redesign_detail.png(선택 상세).

## 추가 확인

- 단지/실행 사례 내비게이션은 고정 예시로 바로 이동하던 동작을 제거하고 해당 종류 검색 목록을 열도록 수정. 좁은 화면에서 결과를 선택하면 검색 패널을 닫음.
- 전체 지도 복귀 시 이전 선택 상세와 주소의 focus 값을 초기화해 현재 지도와 상세의 불일치를 방지.
- 인앱 브라우저: 사례 카드 읽기 후 URL과 지도 30개/32개 연결을 유지. 연결 추가 시 35개/37개로 증가하며 배율 45% 유지, 추가 노드 5개 안내 확인.
- 패널 닫기 후 카메라 배율 유지, 검색 종류에서 해피콜 관리소 제외 및 단지 목록 탐색 확인.
