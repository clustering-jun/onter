# 그래프 스키마와 연결 규칙

## 저장 구조

SQLite `nodes(id,kind,label,attrs,source)`, `edges(id,src,dst,rel,status,weight,year,attrs,source)`, `aliases(alias,node)`, `series(node,data)`, `meta(key,value)`.

`source`는 프로젝트 기준 상대 파일 경로·CSV 행 번호·관련 필드·집계 설명을 담는다. JSONL은 행 번호가 JSONL의 줄 번호이며, CSV의 `source_row`는 별도로 원본 엑셀 행 번호를 뜻한다. 행 번호의 두 의미를 섞지 않는다. 입력 파일과 행 수·SHA256은 `data/manifest.json`에 보존한다. 그래프 DB는 소스의 복사·투영이며 원자료가 아니다.

## 안정적인 노드 키

| 종류 | 키 예시 | 역할 |
|---|---|---|
| 단지 | `complex:KOH_137` | 기존 확정 ID |
| 표준 프로그램 | `program:I02` | 기존 분류 코드 |
| 운영 기록 | `record:comm_00002` | 기존 레코드 ID |
| 필요 분야·대상·자원·기관 유형 | `domain:N4`, `target:OLD`, `resource:RS04`, `partner:OG01` | 기존 코드북의 정의 |
| 사례·레시피·걸림돌 | `case:CB01`, `card:CB01_P1`, `obstacle:CB01_O1` | 사례집의 구조화 키 |
| 기사 | `news:N…` | 기존 뉴스 ID |
| 기관명 | `organization:…` | 기존 기사 기관 연결표의 정확 문자열. 동음이의 기관 통합을 수행하지 않음 |
| 해피콜 조사·관리소·VOC | `survey:<record_id>`, `office:<record_id>`, `voc:<record_id>` | 집계 수준과 출처 유지 |
| 추천 후보 | `recommendation:KOH_137:I02` | 단지×프로그램별 실제 모델 산출물 |

실제 종류별 개수와 입력 파일 목록은 manifest를 기준으로 한다. 구축 시점은 27,172개 노드·125,389개 관계이며 커뮤니티 22,223행을 포함한다.

## 선의 의미

| 상태 | 관계 예 | 허용하는 해석 |
|---|---|---|
| observed | 단지→운영 기록, 사례→레시피, 사례→걸림돌, 확정 단지 연결 | 원표에 해당 연결이 기록되어 있음 |
| defined | 프로그램→분야·통상 대상·통상 자원 | 분류 사전의 정의. 개별 실행 사실·필수 조건 아님 |
| derived | 기록→프로그램, 단지→분류된 운영 이력, 뉴스→프로그램, 후보→사용 근거 | 구조화·집계·규칙 대응 결과 |
| estimated | 단지→필요 분야 지표, 단지→검토 후보 | 모델 추정. 실제 수요·채택·효과 아님 |
| similarity | 구성이 닮은·가까운·혼합 유사 단지 | 해당 기준으로 계산한 유사도. 동일 단지 아님 |
| tentative | 낮은 확신도 분류·기사 유형 연결 | 기본 화면에서는 제외. 검토용으로만 표시 |

## 핵심 조인

1. **운영 기록**: 현재 커뮤니티 NLP의 `complex_id`→단지, `std_id`→프로그램. `program_name_masked`, `activity_content_masked`, `place_masked`만 표시한다. raw 식별 원문은 저장하지 않는다.
2. **단지×프로그램 이력**: `dup_exact_first_flag != 0`인 대표 레코드만 그룹 합계로 센다. 원래 22,223개 기록 노드는 보존하며 중복 제외된 13행도 상세에서 확인 가능하다. 집계 결과는 분류의 영향을 받으므로 derived로 표시한다. 참여인원을 고유 주민 수로 합산하지 않는다.
3. **프로그램 사전**: 기존 코드북·명칭을 정확 대응한다. 통상 자원과 실제 명시된 자원을 별도 관계로 만든다.
4. **사례집**: 확정된 `links/case_complex.csv` 중 `needs_review=0`·유효 ID만 연결. `evidence_cards.std_id`로 유형 연결. 3개 빈 단지 ID 연결은 제외했으며 사례 자체는 남긴다(`data/unlinked.json`).
5. **뉴스**: 기존 article_program/article_complex/article_org 연결표 사용. 미검토 단지 연결은 제외하고 낮은 확신도 유형 연결은 tentative로 분리한다. 기사 제목만 노출하고 본문은 그래프에 넣지 않는다.
6. **해피콜**: 전국 수요·VOC는 조사 허브 아래 보존. 기존 모델의 명시된 문항→분야 대응만 defined 관계로 사용한다. 단지로 이어지는 가짜 수요 관계는 만들지 않는다. 관리소 연결은 사용자 확정표만 사용하고 1:N 관리소는 하나의 점수 노드로 남긴다.
7. **추천**: 기존 3,180개 상세 JSONL을 그대로 투영하고, 추천이 실제 사용한 운영 레코드·카드·뉴스 ID로 근거를 연결한다. 다른 유사 사례를 해당 후보의 직접 근거로 임의 추가하지 않는다.
8. **동적 LLM**: 별도 읽기 전용 API에서 생성 결과를 읽는다. 설명을 그래프 관계로 사용하지 않는다.

## 시간·공간·수량

- 운영 연도 필터는 시작연도별 기록과 해당 연도의 집계에만 적용한다. 모델·사례집·기사는 별도 시점의 참고 근거다.
- 프로그램별 전체 기간 사전 통계와 모델의 시간 분할 평가 통계를 같은 값으로 취급하지 않는다.
- 홈닥터 추이는 관측 월만 그리며 누락 월을 0으로 새로 만들어 넣지 않는다.
- 단지 공간·인구·접근성의 수백 개 속성은 단지 상세의 ‘전체 속성’으로 확인할 수 있다. 고독사 열은 제외했다.
- 매출·효과·실제 예산·필수 인력으로 확인되지 않은 비용·효과·자원은 그러한 사실 관계로 만들지 않는다.

## 화면에서의 표본과 경로

첫 지도는 분야별 기록이 많은 추천 대상 유형 8개씩의 합집합을 표시한다. 관계 수 90은 분야별 12개, 120은 전체 109개 프로그램을 표시한다. 특정 점의 근방은 사례집·레시피를 우선하고 운영 이력 18개·기록 8개·같은 유형을 근거로 쓴 후보 5개 등 관계별 상한을 둔다. 데이터는 삭제하지 않으며 전체 근거 목록·검색으로 탐색한다.

경로 찾기는 무방향 BFS, 최대 5단계이며 각 선의 원래 방향을 표시한다. 지사·범용 분야·대상·기관 허브를 중간에 거쳐 ‘관련 있어 보이는’ 지름길은 제외한다. 이는 인과 추론이나 최적 추천 경로가 아니다.
