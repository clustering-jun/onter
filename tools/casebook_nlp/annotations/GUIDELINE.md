# 주거복지사 활동 사례집 — 사례 구조화 추출 지침 (v1)

목적: 사례 하나를 '복지 프로그램 실행 레시피'로 구조화한다. 두 가지에 쓴다.
1) 추천 후보에 "비슷한 단지는 이렇게 했다"는 근거 붙이기(필요·대상·협력기관·운영 방법·성과)
2) 사업을 시작·운영할 때 부딪힌 문제와 해결법 모으기(예: 지자체 자산 설치 불가, 노인일자리 파견 거부 → 설득)

입력: `CBxx.txt` (머리 5줄에 case_id·부·영역·지역·프로그램, '---' 아래가 사례 원문). 원문 끝에는 대개 요약 상자(프로그램명, 한 줄 설명, '운영 …', '대상 …', 때로 단지 목록)가 있다.

출력: 사례마다 `CBxx.json` 파일 하나(UTF-8, 아래 형식, JSON만). 원문에 없는 내용은 만들지 않는다. 모르면 빈 배열·null.

## 형식

```json
{
  "case_id": "CB01",
  "complexes_mentioned": ["청주산남2"],          // 원문에 나온 단지명 그대로(요약 상자의 단지 목록 포함, '서울번동2·3·5'는 ["서울번동2","서울번동3","서울번동5"]로 펼침)
  "programs": [                                    // 요약 상자 기준. 상자가 없으면 본문에서 사업명
    {"name": "숙골빨래터", "summary": "이불 빨래 수거·세탁·배달·건조 서비스", "operation": "월 1회 신청 접수", "target": "65세 이상 어르신, 장애인과 같은 거동 불편자",
     "start": "2021년 2월", "evidence": "<원문 그대로>"}
  ],
  "elements": [
    {"type": "need", "text": "<한 문장 요약>", "value": 34, "unit": "%", "evidence": "<원문 그대로>", "speaker_role": "주거복지사"}
  ],
  "obstacles": [
    {"obstacle": "<부딪힌 문제 한 문장>", "obstacle_category": "기관 협조", "obstacle_evidence": "<원문 그대로>",
     "solution": "<어떻게 풀었나 한 문장, 원문에 없으면 null>", "solution_strategy": "설득·협상", "solution_evidence": "<원문 그대로 또는 null>",
     "status": "해결"}
  ],
  "summary": "<사례 전체를 2문장으로: 어떤 필요에 누가 무엇을 어떻게 했고 무엇이 달라졌나>"
}
```

## elements.type (하나의 사실 = 한 행, 사례당 보통 10~25행)
- `need`: 입주민의 문제·필요·상황(실태조사 결과, 수치 포함)
- `target`: 대상(누구를 위한 것인가, 선정 기준)
- `partner`: 협력 기관·단체·사람과 그 역할. `partner_name`에 기관명, `role`에 역할을 추가로 넣는다
- `resource`: 공간·예산·인력·물품·재원 출처(공모사업 등)
- `operation`: 운영 방법(주기, 절차, 신청 방식, 인력 구성, 단계, 도구·검사지)
- `outcome`: 성과·변화(이용 횟수, 참여 인원, 예산 절감, 입주민 변화). 숫자가 있으면 value·unit
- `lesson`: 주거복지사가 말한 노하우·교훈·다른 단지가 참고할 점·향후 계획

## obstacles (사업 시작·운영 중 부딪힌 문제와 해결. 없으면 빈 배열)
- obstacle_category 중 하나: `공간·시설`, `예산·재원`, `인력`, `기관 협조`, `제도·규정`, `주민 참여·신뢰`, `정보·인식 부족`, `대상자 특성`, `운영 부담`, `기타`
- solution_strategy 중 하나(해결이 원문에 있을 때): `설득·협상`, `대체 자원 연계`, `주민 참여 유도`, `외부 공모·후원`, `제도·규정 활용`, `단계적 확대·시범 운영`, `방식 변경`, `관계 형성·신뢰 쌓기`, `기타`
- status: `해결`, `일부 해결`, `진행 중`, `미해결`
- 문제는 '입주민의 어려움'(need)이 아니라 '사업을 하는 쪽이 부딪힌 장애'다. 예: 지자체가 자산 외부 설치 불가, 시니어클럽이 공단은 복지 사업자가 아니라 파견 불가, 대상자가 문을 열지 않음, 참여가 저조함, 예산이 없음.

## 공통 규칙
- `evidence`는 반드시 원문에서 **그대로 복사**한 연속 구간(250자 이하). 띄어쓰기·문장부호까지 같게. 바꿔 쓰거나 줄이지 않는다(자동으로 대조한다).
- `speaker_role`: `주거복지사`, `입주민`, `협력자`(자활근로자·기관 담당자·봉사자 등), `서술`(필자 서술·요약 상자)
- 사람 이름은 `text`·`summary`·`obstacle`·`solution`에 쓰지 않는다(역할로 쓴다: "주거복지사", "입주민"). evidence에는 원문 그대로 둔다(나중에 가린다).
- 수치는 원문에 있는 것만. 단위: 회, 명, 세대, 가구, %, 원, 만 원, 개, 대, 곳, 년, 개월 등.
- 사례집은 각색이 섞여 있으니 판단·평가를 덧붙이지 않는다.
